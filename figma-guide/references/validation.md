# validation.md

本文件只讲收尾验证与父框改动后的安全流程。

## 1. 验证三步法

每个任务完成后，至少做三层验证：

1. **结构层**：确认关键节点存在、位置正确、层级未漂移。
2. **视觉层**：导出目标节点，生成 PNG。
3. **业务层**：打开截图逐项检查，确认没有肉眼可见问题。

导出成功不等于视觉正确。真正交付以前，必须看图。

## 2. 截图必 Read

导出结果常见的“成功但仍然错误”包括：

- 文字被裁切。
- 颜色落到错误值。
- 元素被遮挡或覆盖。
- 实例 override 没生效。
- 间距或对齐出现 1–2px 漂移。

因此必须遵守：

- 导出后先写盘。
- 打开 PNG 逐项确认。
- 没有看过图，就不能向用户报告“已完成”。

## 3. 截图核对清单

看图时重点检查：

- [ ] 文字是否完整，无截断、无超框。
- [ ] 颜色是否与设计要求一致。
- [ ] 是否有遮挡、重叠、层级错误。
- [ ] 卡片、列表、按钮之间的间距是否均匀。
- [ ] 圆角、描边、阴影是否符合项目 token。
- [ ] 父框与子节点是否对齐。
- [ ] 实例状态和 override 是否真的生效。

## 4. 截图保存原则

推荐目录：

```text
<项目根>/temp/figma/
```

建议流程：

1. 首次保存前确保目录存在。
2. 导出结果先落盘为 PNG。
3. 若重复导出同一张图，避免误读旧文件。
4. 命名带页面或功能语义，便于回看。

## 5. `figma-save-export.mjs` 的使用时机

适用场景：

- 已拿到导出结果的 base64。
- 需要把结果可靠写成 PNG。
- 希望自动做 PNG magic 校验，避免写出伪图片。

它只负责：

- 解码 base64。
- 校验 PNG 头。
- 写到磁盘。
- 输出写盘结果 JSON。

详细参数与退出码见 `references/scripts.md`。

## 6. 改父框尺寸时的强制流程

只要改复合结构父框 `w / h`，就按下面流程执行：

### Step 1：先查越界基线

先运行 `figma-validate-bounds.mjs`，确认当前是否已存在越界：

- 左/上溢出。
- 右/下溢出。
- 被裁切但你之前没注意到的局部问题。

这一步的目的是拿“改之前”的基线，避免把旧问题误当成新问题。

### Step 2：需要重算时，用 `figma-resize.mjs`

如果父框尺寸变化会影响内部排布：

- 不要手算每个子节点的新坐标。
- 用 `figma-resize.mjs` 生成 plan。
- 根据 plan 应用新的位置 / 尺寸。

### Step 3：改完后再查一次越界

父框改完、子节点更新完之后，必须再次运行 `figma-validate-bounds.mjs`。

只有在越界为 0 时，这轮父框改动才算通过。

## 7. 完工前自检

- [ ] 重复结构已优先复用，没有重复重画。
- [ ] 组件定义留在组件页，UI 页只消费复用结果。
- [ ] 关键节点已重新读取验证，没有继续使用旧 NodeId。
- [ ] 颜色 / 字号 / 圆角 / 间距遵循项目设计系统。
- [ ] 新 Section 已复刻现有模式，而不是凭印象设尺寸。
- [ ] 父框改动前后都走过 bounds 检查。
- [ ] 需要重算的子节点已通过 resize plan 处理。
- [ ] 导出图已经写盘，并实际打开检查过。
- [ ] 用户看到的结论基于截图核对，不是基于“导出成功”。
