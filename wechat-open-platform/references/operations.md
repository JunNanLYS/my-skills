## 应用基本信息规范

### 应用名称

| 规则 | 内容 | 注意事项 |
|------|------|---------|
| 唯一性 | 需保证唯一识别性和客观性 | 不得与政府机关、官方机构混淆 |
| 空格 | 字母间最多只允许**一个空格** | 两个及以上空格会被驳回 |
| 长度 | 不超过**10 个中文字符**或**20 个英文字符** | 不得含有特殊字符（如 #、& 等） |
| 营销 | 不得包含广告口号、标语等营销推广内容 | 如"xx赚"、"xx分享"会被驳回 |
| 平台字样 | 不同平台版本共用 AppID，名称不得出现平台字样 | 如"Android版"、"iOS版"会被驳回 |
| 测试字样 | 不得出现测试相关字样 | 如"test"、"测试"会被驳回 |
| **品牌词** | **禁止包含商标/品牌字样** | 微信、腾讯、小程序、公众号、小米、百度、360、魅族、vivo 等均不可用 |
| 重复 | 不得与已有应用名称重复 | 需提供资质或授权 |

### 应用图标

- 必须**清晰**，不能含有水印信息
- 需与应用名称保持一致
- 不得包含腾讯、微信等官方品牌标识

## 应用主体要求

### 主体一致性规则

**官网主体信息**或**应用市场下载链接开发者信息**需与微信开放平台认证主体信息**一致**。

### 不一致时的处理方式

| 主体类型 | 需提供的补充材料 |
|---------|----------------|
| 企业主体 | 授权书（需说明授权关系+授权内容，**加盖双方公司公章**） |
| 个人主体 | 授权书（**个人签名即可**） |

### 个人开发者特殊要求

如申请已上架应用但未认证开放平台账号主体，需提供：
- **软件著作权证书**（著作权人需与账号主体一致）
- **手持身份证照片**（身份证信息需与账号主体一致）
- 应用市场下载链接开发者信息也需一致

## 应用类目规范

### 核心规则

- **应用服务范围 <-> 填写类目 <-> 实际提供服务** 三者必须一致
- 申请或变更应用前**需先添加匹配的类目**
- 操作路径：`微信开放平台后台 -> 管理中心 -> 应用类目 -> 添加应用类目`

### 类目管理注意事项

- 类目不匹配时可**删除现有类目**，删除不会影响之前关联该类目的应用
- 类目分为**个人类目**与**非个人类目**
- 部分类目需先完成**开发者资质认证**后才可选择

## 应用官网规范

### 官网内容要求

必须包含：
- 应用提供的服务功能详情
- 用户协议
- 版权所有者
- 网站备案信息
- 联系方式
- **应用名称字眼**及其应用介绍、应用图片

### 官网形式限制

| 不支持的形式 | 说明 |
|-------------|------|
| 手机端小程序页面 | 会被驳回 |
| 公众号页面 | 会被驳回 |
| H5 页面 | 会被驳回 |
| 纯登录界面 | 需提供账号密码供审核 |
| 仅几行文字 | 不符合常规网站要求 |
| 仅一张/几张图片 | 会被驳回 |
| 文档形式 | 会被驳回 |

### 官网主体一致性

- 官网开发者信息需与微信开放平台认证主体**一致**
- 不一致时需提交**授权书（加盖双方公章）**

## 应用市场下载链接规范

### 基本要求

- 应用已上架时可勾选"是"并提供**有效应用商店下载链接**
- 应用已上架时，微信开放平台账号主体**需先通过认证**

### 合规的下载链接来源

| 合规来源 | 不合规来源 |
|---------|-----------|
| 应用宝 | APK 直接下载链接 |
| App Store | 非应用商店链接 |
| 谷歌商店 | 无法正常打开的链接 |
| 小米应用商店 | 无相关下载按钮的链接 |
| 华为应用商店 | 无应用开发商信息的链接 |
| vivo 应用商店 | 无应用相关信息的链接 |

## 应用流程图规范

| 应用状态 | 可提交内容 |
|---------|-----------|
| **已上架** | APP 运行截图 + 应用商店下载链接 |
| **未上架** | 交互设计图 或 运行流程逻辑图 |

### 流程图要求

- 内容需与应用名称/图标/官网保持一致
- 必须是 **APP 流程图或交互设计图**
- **建议包含状态栏**（时间、电量等信息）以校验真实性
- 不合格：图标、小程序截图、公众号/网站截图

---

## 特别应用规则

### 游戏应用

- 已上架的游戏应用需附上**《网络游戏出版物号》**等材料
- 游戏出版单位与开放平台认证主体不一致时，需补充：
  - 版权方与开放平台主体方的**授权文件**
  - 授权书需**加盖双方公章**，且至少一方为**鲜章**
- 无法提供以上材料的，申请时在"应用已上架"处**勾选"否"**

### 企业内部使用应用

| 要求项 | 具体说明 |
|-------|---------|
| 主体认证 | **必须先通过**微信开放平台主体认证 |
| 申请说明 | 需注明"该应用是只限内部使用，不做他用" |
| 流程图 | 需上传能清晰说明仅限内部使用的流程图，或提交仅限内部使用的**盖章说明** |
| 已上架=是 | 可提交同一开放平台主体下**其他应用**的下载链接 |
| 已上架=否 | 可提供与开放平台账号主体**一致的企业网站** |

## 网站信息登记表规范

### 内容一致性

登记表中的应用内容需与开放平台内应用基本信息**完全一致**。

### 公章要求

| 场景 | 要求 |
|-----|------|
| 一般情况 | 公章需与登记表内主办单位/开放平台认证主体**一致** |
| 港澳/海外主体无公章 | 可用**有权人手写签名**替代 |
| 公章类型 | **仅支持公司公章**，不支持合同章等其他章 |
| 公章清晰度 | 需**清晰且规范** |

### 备案号格式

正确格式：`粤ICP备XXX号` 或 `粤ICP备XXX号-1`，备案需与登记表内主办单位一致。

## 关键风险提示汇总

1. **品牌词红线**：应用名称中绝对不能出现微信、腾讯、小程序、公众号及竞品品牌词
2. **主体一致性**：官网/应用市场/开放平台三方主体必须一致，不一致必须提前准备授权书
3. **官网质量门槛**：官网不能是 H5、不能是纯图片/纯文字、不能是登录墙，必须有完整信息
4. **流程图真实性**：必须有状态栏，不能拿小程序截图冒充 APP 截图
5. **游戏类特殊合规**：出版物号 + 授权文件 + 鲜章，缺一不可（否则勾选未上架）
6. **登记表公章**：只认公司公章，合同章无效
